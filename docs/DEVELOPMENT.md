真机发现固件的标准 Dream 配置关闭，实际屏保来自小米应用。接入 `com.duokan.intent.action.show.screensaver` 与退出广播，临时缩短空闲时间验证自动启动后恢复原值。没有删除原厂应用或取得 root。

曾出现侧栏打开后整张时钟被缩小的问题，已改为根据剩余宽度计算卡片位置和大小，公历、农历分行，文字保持可读尺寸。

公开仓库只保存通用代码和空白示例。实测家庭数据、电视地址、调试截图和签名留在本机。

## 语音输入兼容性检查

该真机未注册标准 `android.speech.RecognitionService` 或 `android.speech.action.RECOGNIZE_SPEECH` Activity。单靠标准 SpeechRecognizer 不能直接调用电视的小爱识别。

0.5.1 新增「设置 → 遥控器语音输入测试」。选中前台 EditText 后请求输入法，真机搜狗输入法成功建立 InputConnection，界面显示「按住语音键说话」。用户实际按住遥控器语音键说话后，测试 Activity 的 EditText 成功收到完整中文短句，TextWatcher 和 UI 状态均确认文字回填。因此可沿用前台输入法做语音文字录入；尚不支持屏保首页无输入框时直接接管小爱，也未将测试文字自动写入库存或日程。

0.6.0 将测试页升级为正式录入与确认页。初步测试发现 0.8B 模型直接处理完整日期时间字段不稳定，因此日期、时刻、出发时间与必须完成标记改由确定性规则处理。模型只输出 title，并校验是否来自原文，失败则保留规则标题。真实电视语音测试已确认「明天下午四点十分接孩子，下午四点出发」的日期和两个时间显示正确。规则覆盖 18 个正常输入、14 个缺失/冲突输入及跨年边界；局域网实时接口 6 例通过，并验证未授权请求被拒绝。模型运行与草稿服务独立于原有模型服务，服务和模型文件不在公开仓库。

真机 instrumentation 已验证：解析不写入日程、确认后只新增一条、取消不保存、缺少具体时间时阻止保存。测试结束清理自建日程及提醒。部署的服务移出 macOS 受保护的 Documents 目录后，用独立 LaunchAgent 维持运行；并从电视实际请求健康检查确认可达。

0.7.0 加入冰箱语音草稿接口与库存版本校验。用户实测发现输入法有时漏掉开头动作，只返回「了两盒……」，因此增加残留语气词清理、明确选择增减方向、输入页先选冰箱及结构化库存上下文。服务参考库存补全简称，模型仍只负责食材名；数字和操作由规则控制。真机在独立测试冰箱中验证新增、补货、指定批次扣减、归零移除、库存不足、单位不符、过期草稿、取消、上下文补全和截断输入，结束后确认其他家庭库存一致并移除测试冰箱。

0.7.1 修复产品在前、冰箱在句尾时残留介词，以及数字和中文楼层名不一致导致匹配失败。放入时唯一匹配的已有批次自动选中，明确新批次或不同保质期仍独立保存。新增基于相近库存的分区候选及匹配度，明确分区优先；分数作为参考，不解释成真实概率。使用用户原句在真实库存上做只读回放，已确认指定冰箱、已有产品及库存预览正确，测试未更新库存。


## 0.8.4

加入手机/桌面网页库存编辑、会话登录、SQLite 版本库存和冲突留存。网页和电视使用 WebSocket 更新通知，连接或重连后通过 HTTP 拉取；HTTP 写入继续执行版本校验和幂等保护。电视本地写入改为同步持久化，避免进程退出丢失数据。系统后台任务与低频 HTTP 补同步保留。

数字默认字体为 Oswald 600；私有字体覆盖支持 Fliqlo Regular，仅本地使用，未提交字体原文件。重新按字形边界计算数字尺寸和基线。

验证：21 项 Python 测试、6 项日期倒计时检查及 APK 构建通过；真机独立测试库存验证网页拉取、电视写入确认；浏览器验证 WebSocket 更新、重连，网页修改在 7 秒内获电视版本确认。已清理自建测试冰箱。


## 0.9.0

日程栏加入「即将到期 / 最近添加 / 已过期」三个左右切换 Tab，分别按到期时间升序、创建时间降序、过期时间降序排列。「最近添加」保留已完成事项以便恢复；今日必办事项以当天结束作为过期界限。旧事件首次加载补齐 createdAt，编辑保留创建时间。

通知与前台提醒携带 taskId 和提醒阶段，自动选择分类、滚动到事件、聚焦并短暂高亮。出发和开始提醒定位同一事件，卡片标明本次提醒阶段。各 Tab 保留滚动位置。独立真机检查覆盖创建时间、到期分类、排序、分类切换、广播定位和完整卡片可见性，测试事件按唯一 ID 清理。
